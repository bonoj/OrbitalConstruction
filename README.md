# Orbital Construction

![Orbital Construction reference](ORBITAL_CONSTRUCTION_REFERENCE.png)

**An executable laboratory for discovering orbital construction vocabulary through physical composition.**

Orbital Construction asks whether a small set of semantically meaningful parts can compose into materially different, convincing orbital facilities without turning every new structure into a bespoke model.

The current E2 vocabulary contains **37 named module kinds across seven realization families**. Junctions, pressure modules, habitation, work platforms, structure, machines, and terminations share explicit connection interfaces and remain meaningful even when nothing is attached to them.

The stations are not the product. **They are evidence.**

## Explore

Open **[the standalone simulation](./index.html)** to inspect and manipulate the current construction system.

Orbit, pan, select, isolate, attach, detach, roll, and move branches. A single-module bench exposes individual catalog pieces; larger compositions test whether the same vocabulary survives substantially different organizations.

The artifact also preserves the project's earlier station, interior, pallet lander, cargo machinery, and orrery as executable archaeology.

## Construction principles

A few ideas have survived repeated implementation pressure:

- **Modules are complete before connection.** An unused interface is still a finished physical boundary.
- **Connections are semantic.** Ports carry position, orientation, family, size, occupancy, and a canonical frame.
- **Envelope precedes decoration.** Detail follows the actual geometry and function of the object.
- **Interfaces own their space.** Connection corridors constrain nearby generated detail.
- **Surface is not form.** Texture can enrich construction, but cannot substitute for it.
- **Meaning survives optimization.** Batched geometry retains semantic ownership.
- **Composition is a test.** New assemblies should exercise shared vocabulary rather than hide bespoke generators.

## Semantic surface

The executable carries the detailed current contract and its retained development archaeology.

**[SEMANTIC_SURFACE.md](./SEMANTIC_SURFACE.md)** is the human/model orientation layer: what the project is, what its abstractions mean, what it deliberately does not claim, and how to extend it without prematurely inventing architecture.

The working rule is simple:

> **Build evidence. Promote what earns meaning.**
